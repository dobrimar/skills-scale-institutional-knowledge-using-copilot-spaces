# OctoAcme Project Management Docs

This folder contains the core project management guidance used by OctoAcme. Together, these documents describe the end-to-end lifecycle for turning an idea into a delivered, well-governed project: validate the need, plan the work, execute in a disciplined way, manage risk and communication, release safely, and capture learning for continuous improvement.

OctoAcme’s process starts with project initiation and stakeholder alignment. Teams confirm the problem, agree on goals and success metrics, identify key stakeholders, and create a lightweight project one-pager before moving into planning. Once the initiative is approved, the team defines scope, prioritizes the backlog, estimates work, sets milestones, and documents the Definition of Done so delivery is measurable and predictable.

During execution, the team tracks progress with daily standups, weekly syncs, demos, and project board updates. Work is broken into small, reviewable increments, PRs include issue links and acceptance criteria, and quality gates such as tests, linting, security checks, and manual QA ensure the product remains reliable. Risks, dependencies, and communication needs are managed in parallel so blockers are surfaced early and escalated through clear ownership paths.

When a release is ready, OctoAcme follows a deployment checklist, smoke tests, and rollback planning to reduce operational risk. After each sprint or milestone, teams run retrospectives to identify what went well, what needs improvement, and which actions should be tracked in the backlog. The project roles and personas described in these docs clarify ownership and help cross-functional teams work effectively across the full lifecycle.

## Core Process Summary

OctoAcme uses a practical, cross-functional project management model built around clear roles, established cadence, and measurable outcomes. Product managers define value and success metrics, project managers coordinate planning and communication, developers deliver and test the work, QA validates acceptance criteria, and stakeholders provide input and approvals. The documents emphasize iterative delivery, transparency, and accountability so teams can make decisions using evidence rather than assumptions.

## How to Use These Docs

Start with the [Project Management Overview](octoacme-project-management-overview.md) for the big picture, then move into the specific guide that matches the phase of work you are in. Use the initiation and planning docs when shaping a project; use the execution, risk, and release guides while delivering; and use the retrospective doc to improve the process over time.
